# Configuration

## Precedence

Highest wins:

```
1. CLI arguments          --model, --permission, --cwd, --sandbox
2. Project configuration  {workspace}/.kodo/settings.json  → "kodo" block
3. User configuration     ~/.kodo/config.json
4. Environment variables  OPENAI_API_KEY, OPENAI_BASE_URL, DEFAULT_MODEL
5. Built-in defaults
```

**The environment sits BELOW the config files deliberately.** A shell that
happens to export `OPENAI_API_KEY` — a leftover from another tool, or a CI
secret injected for a different job — must not silently outrank the key you
saved with `kodo config set`. That is how a run ends up billed to the wrong
account with nothing in the output saying so. The environment is a fallback for
machines with no config, which is exactly the container case.

`kodo config list` shows the source of every value:

```
  model                  gpt-4.1-nano (user)
  permission             auto (defaults)
  ui.port                4173 (defaults)
```

## User configuration

`~/.kodo/config.json`, written mode `0600`. Managed with `kodo config`.

```bash
kodo config set model gpt-4.1-nano
kodo config set apiKey sk-your-key
kodo config set baseUrl https://api.openai.com/v1
kodo config set permission ask
kodo config set ui.port 4173
kodo config set server.port 9000
kodo config list
kodo config path
```

### Keys

| Key | Default | Meaning |
|---|---|---|
| `model` | — | Model name sent to the provider. Required. |
| `apiKey` | — | Provider API key. Required. Never printed. |
| `baseUrl` | `https://api.openai.com/v1` | OpenAI-compatible endpoint. |
| `provider` | — | Optional label, reported by `kodo status`. |
| `permission` | `auto` | `auto`, `ask`, or `plan`. |
| `ui.port` | `4173` | Default port for `kodo ui`. |
| `ui.host` | `127.0.0.1` | Default UI bind address. |
| `server.port` | `9000` | Default port for the Local API. |
| `server.host` | `127.0.0.1` | Default API bind address. |

## Project configuration

`{workspace}/.kodo/settings.json`. Belongs in version control — so **never put
an API key here**.

```json
{
  "kodo": {
    "permission": "ask"
  },
  "permissions": {
    "allow": ["Bash(pytest:*)"],
    "ask":   ["Bash(git push:*)"],
    "deny":  ["Bash(rm:*)"]
  },
  "hooks": {
    "PreToolUse": [
      { "matcher": "write_file",
        "hooks": [{ "type": "command", "command": "./scripts/audit.sh" }] }
    ]
  },
  "mcpServers": {
    "playwright": { "command": "npx", "args": ["@playwright/mcp", "--headless"] },
    "remote":     { "type": "http", "url": "https://example.com/mcp" }
  }
}
```

The `kodo` block holds CLI configuration overrides. `permissions`, `hooks` and
`mcpServers` are read by the agent — see [permissions.md](./permissions.md) and
[mcp.md](./mcp.md).

### `KODO.md`

Project instructions loaded into every request. Generated by `kodo init`, and
meant to be edited by hand afterwards. Commit it.

## Environment variables

| Variable | Effect |
|---|---|
| `OPENAI_API_KEY` | API key, when no config file has one. |
| `OPENAI_BASE_URL` | Provider endpoint. |
| `DEFAULT_MODEL` | Model name. |
| `KODO_PERMISSION` | Permission mode. |
| `KODO_HOME` | Override `~/.kodo`. Used by the test suite to avoid touching your real state. |
| `KODO_CORE_PATH` | Path to Kodo Core's `core/index.mjs`. |
| `KODO_SOURCE_DIR` | The checkout a source install points at. Set by the launcher. |
| `KODO_DOCKER_IMAGE` | Image for `--sandbox docker` (default `node:22-bookworm-slim`). |
| `KODO_INCUS_IMAGE` | Image for `--sandbox incus` (default `images:debian/12`). |
| `KODO_ALLOWED_ORIGIN` | Pin the API's CORS origin to one exact value. |
| `KODO_DISABLE_BASH` | Set to `1` to remove shell execution from the agent entirely. |
| `NO_COLOR` | Disable colour output. |

A `.env` file in the repository root or `backend1/` is loaded automatically.
Values already set in your shell always win.

## Secrets

Kodo never prints a credential:

- `kodo config get apiKey` prints a mask (`sk-••••••••ab`).
- `kodo config list` masks every key that looks like a secret, including nested
  ones such as `mcpServers.x.env.TOKEN`.
- `kodo status --json` and `kodo doctor --json` omit keys entirely.
- Server logs never record credentials.
- Child processes get a sanitised environment, so an allowlisted `npm` script
  cannot read `OPENAI_API_KEY` and exfiltrate it.
