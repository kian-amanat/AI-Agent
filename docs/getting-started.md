# Getting started

From "I have a computer" to "an agent is working on my project".

## 1. Check Node

```bash
node --version
```

You need **20.12 or newer**. If you do not have it, install from
[nodejs.org](https://nodejs.org) or your package manager.

## 2. Install Kodo

```bash
npm install -g kodo-agent@next
```

That is the whole installation. The package ships the CLI, Kodo Core and the
prebuilt production web UI, and npm resolves its dependencies for your platform
— there is nothing else to install and nothing to build.

> Prereleases are published to the `next` tag. Drop `@next` once a stable
> release is out.

Contributing to Kodo instead? See
[installation.md](./installation.md#from-source-contributors) — a source
checkout does need its dependencies installed, and that is the only case that
does.

```bash
kodo --version
```

If that says `command not found`, `~/.local/bin` is not on your PATH — see
[installation.md](./installation.md#path).

## 3. Point Kodo at a model

Kodo talks to any OpenAI-compatible provider.

```bash
kodo config set model gpt-4.1-nano
kodo config set apiKey sk-your-key-here
kodo config set baseUrl https://api.openai.com/v1
```

Check it:

```bash
kodo doctor
```

You want `✓ Provider` and `✓ API connection`. Anything red is explained in
[troubleshooting.md](./troubleshooting.md).

## 4. Set up your project

```bash
cd ~/projects/my-app
kodo init
```

This creates `.kodo/` and generates `KODO.md` — project instructions Kodo loads
into every request. It is generated by reading your repository, and validated
against real files before being written.

Commit `KODO.md` and `.kodo/settings.json`. **Do not** put an API key in
`.kodo/settings.json`; keys belong in `~/.kodo/config.json`.

## 5. Run the agent

Interactive:

```bash
kodo
```

```
> the login button doesn't disable while the request is in flight — fix it
```

One-shot:

```bash
kodo run "fix the failing tests"
```

## 6. Try the web UI

```bash
kodo ui start --open
```

This starts the Local API and the Kodo web interface, and opens your browser.

The project it works on is **the directory you ran it from** — the one printed
as `Workspace:` in the output. You can start chatting straight away; there is
nothing to connect and no folder to pick, and VS Code is not involved. To work
on a different project, run `kodo ui start` from that directory (or pass
`--cwd`). See [ui.md](./ui.md).

When you are done:

```bash
kodo ui stop
```

## 7. Pick up where you left off

```bash
kodo sessions
kodo resume a1b2c3
```

## Being careful the first few times

The agent edits files and runs commands as you. Some ways to keep control:

```bash
# Commit first — the cleanest undo there is.
git commit -am "before kodo"

# Make Kodo ask before its first change.
kodo chat --permission ask

# Let it explore and plan, but change nothing.
kodo chat --permission plan

# Run it inside a container instead of on your machine.
kodo run "upgrade all the dependencies" --sandbox docker
```

See [permissions.md](./permissions.md) and [sandboxing.md](./sandboxing.md).
